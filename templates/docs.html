  • Өдөр тутмын ажил — Dashboard, Ажлын даалгавар (Inbox + Leads + Issues нэгтгэсэн 5 таб), Message Logs.
  • Бизнесийн удирдлага — Ерөнхий мэдээлэл / Бизнесийн нэгжүүд / Ажилтнууд. Нэгжийн нэр дээр дарж тухайн нэгжийн сургалт/үйлчилгээ/бүтээгдэхүүнийг шууд удирдана.
  • Ботын удирдлага — AI сургалт / Handover түлхүүр үгс / FAQ (+ чатнаас гарсан асуултууд) / Ботын тохиргоо.
  • Шинэ боломж: Course / Service / Product бүрд олон линк (description / URL / note) нэмж болно. FAQ хэсэгт OpenAI ашиглан жинхэнэ чатнаас гарсан асуултуудыг автомат бүлэглэх боломж.

1. Танилцуулга

Magic Bot бол Facebook Page чатанд ирсэн мессежид AI-аар автоматаар хариулдаг систем. Та энэ админ панелаас ботын зан төлвийг тохируулж, лид, асуудал, мессежийн бүртгэлийг харж, зайлшгүй шаардлагатай үед өөрөө гар оруулж болно.

Гол санаа: бот 80% энгийн асуултанд хариулна, үлдсэн 20%-д (гомдол, ажилтантай шууд ярих хүсэлт г.м.) Telegram-аар тантай холбогдоно.

2. Dashboard

Дөрвөн үндсэн үзүүлэлт:

  • Leads — утсаа үлдээсэн нийт лидийн тоо.
  • Open Issues — шийдэгдээгүй handoff болон бусад асуудал.
  • Total Messages — ботоор дамжсан нийт мессеж.
  • Hot Prospects — үнэ асуусан, бүртгүүлэх хүсэлтэй болсон ч утсаа үлдээгээгүй хэрэглэгчид.

3. Лидүүд (/admin/leads)

Хоёр таб:

3.1 Бүртгэгдсэн лид

Утсаа чатанд бичсэн хэрэглэгчид. Ботын дугаар таних регекс (?:\+?976[\s-]?)?[89]\d{7} (Монгол утасны 8 оронтой 8/9-р эхлэх дугаар) ашигладаг. Утас илэрсэн даруйд is_lead = True болж, "Холбогдсон" төлөвт орно.

3.2 Халуун сонирхогч (Hot Prospects)

Үнэ асуусан буюу бүртгүүлэх хүсэлтэй боллоо гэх сигнал илгээсэн ч утсаа үлдээгээгүй хэрэглэгчид. Тэдний сүүлд бичсэн мессеж, цаг, нийт мессежийн тоог харж өөрсдөө идэвхтэй холбогдох боломжтой.

3.3 Нэр шинэчлэх

"Unknown" нэртэй хэрэглэгчид байвал "Нэр шинэчлэх" товчоор Facebook-аас дахин татаж болно. Хэрэглэгчийн нэр анх амжилтгүй татагдсан (Facebook апп Development mode-д байсан гэх мэт) тохиолдолд хэрэглэгддэг.

4. Handoff & Issues (/admin/issues)

4.1 Handoff гэж юу вэ

Бот хэрэглэгчид өөрөө хариулж чадахгүй гэж шийдсэн үед "ажилтан холбогдоно" гэж хариулаад, автомат хариултаа тогтоосон цагаар (анхдагч 2 цаг) зогсооно. Хэрэглэгчийн асуултыг тус хуудсанд issue болгон бүртгэж, Telegram-аар админ багт мэдэгдэнэ.

4.2 Бот чимээгүй болсон хэрэглэгчид

Хуудсын дээд хэсэгт байгаа шар картанд handoff авсан, одоо ботын автомат хариулт нь түр зогссон хэрэглэгчид харагдана. Танд цаг хүлээх шаардлагагүй болсон тохиолдолд "Bot-ыг асаах" товчоор автомат хариултыг шууд сэргээж болно (тестийн үед маш хэрэгтэй).

4.3 Issue-н төлөв

Issue нь Open / In Progress / Resolved төлөвтэй. Та шаардлагатай үедээ status-ийг гараар сольж болно.

5. Чатын лог (/admin/logs)

Сүүлийн 100 мессежийг хугацааны эсрэг дарааллаар харуулна. Хайх талбараас тодорхой нэр, утсаар хайх боломжтой. "Export Logs" товчоор CSV болгож татаж авч болно.

6. Сургалтын анги (/admin/courses)

Бот үе шатанд тохирсон анги санал болгохын тулд энэ жагсаалтыг ашиглана. Анги нэмэхдээ:

  • Course Name — бүтэн нэр (жишээ: "Нягтлан-Нярвын хосолсон сургалт — Танхим")
  • Course Type — 100% Online / Hybrid / Online with Teacher / Classroom
  • Start Date, Time, Price — анги эхлэх огноо, цаг, төлбөр
  • Description — товч тайлбар (бот эндээс эшилж хариулна)

7. FAQ (/admin/faq)

Түгээмэл асуулт-хариултыг бот системийн заавартай хамт уншиж хариулна. Категориудаар нь ангилж бичих нь хайхад илүү тохиромжтой. Шинэ асуулт олон удаа давтагдах юм бол FAQ болгож нэмж бай.

8. Ботын сургалт (/admin/training)

Гурван хэсэгтэй:

8.1 Persona (Дүр)

Ботын "хэн би вэ" гэдэг танилцуулга. Жишээ: "Та Мэжик Санхүүгийн Группын Facebook чат туслах..." Энэ нь системийн зааварчилгааны эхний өгүүлбэр. Аяг ширэгийг хэрхэн авч явахыг тодорхойлно.

8.2 Суурь агуулга (Base intro)

Компанийн ерөнхий танилцуулга — 1 удаа бичдэг урт блок. Энд бизнесийн талаарх ерөнхий мэдээллийг бичнэ. Хоосон үлдээвэл Render-ийн TRAINING_CONTENT орчны хувьсагч, эсвэл pasted_content.txt файл ашиглагдана.

8.3 Нэмэлт тайлбарууд (Snippets)

Энэ хэсэг хамгийн чухал. Бодит чатанд бот алдаа хийх бүрд энд нэг шинэ snippet нэмж бай. Жишээ:

  • "PocketZero-оор төлөх дэлгэрэнгүй" (Гарчиг)
  • "Төлбөр" (Ангилал)
  • "Өндөр" эсвэл "Энгийн" (Ач холбогдол)
  • "PocketZero нь Khan Bank-ийн... " (Агуулга)

Олон удирдлагатай зэрэгцэн ажиллах гол давуу тал нь нэгнийхээ ажлыг дарж бичихгүй. ★ Өндөр ач холбогдолтой snippet нь хариултанд илүү жинтэй нөлөөлнө.

9. Багийн гишүүд (/admin/team)

Бот "Багш хэн бэ?", "Татварын асуудлыг хэн хариуцдаг вэ?" гэх асуултанд хариулахын тулд энэ жагсаалтыг ашиглана. Гишүүн бүрт:

  • Нэр (заавал)
  • Албан тушаал — Жишээ: "Ахлах багш", "Хариуцагч"
  • Мэргэшил — Жишээ: "Татварын тайлан, Magic Finance программ"
  • Тайлбар — товч намтар (1-2 өгүүлбэр оновчтой)

Идэвхгүй болгох тохиргоо нь "одоохондоо чөлөөтэй байгаа гишүүн"-ийг ботод үзүүлэхгүй байх боломж олгоно.

10. Бусад үйлчилгээ (/admin/business-lines)

Facebook хуудас бол компанийг сурталчилдаг боловч бот зөвхөн сургалтын хариулт өгөх ёсгүй. Энд Magic Finance программ, тайлан гаргах үйлчилгээ гэх мэт компанийн бусад чиглэлийг бүртгэж, ботын үйлдлийг сонгож өгнө:

  • Хариулах (Answer) — товч мэдээлэл өгөөд, дэлгэрэнгүйг ажилтнаас лавлахыг санал болгоно.
  • Чиглүүлэх (Refer) — өөрөө хариулахгүй, утас аваад ажилтанд дамжуулна (handoff үүсгэнэ).

11. Settings (/admin/settings)

11.1 Хүний хариу хэсэг
  • Илрүүлэх мэдрэмж — handoff хэр амархан гарахыг тохируулна.
    • Болгоомжтой — зөвхөн "ажилтан/оператор/менежертэй ярья" гэх мэт тодорхой үгстэй мессежид.
    • Дунд зэрэг — гомдол, шүүмжлэлийн үгсийг мөн оруулна.
    • Идэвхтэй — давтан асуух, ойлгомжгүй гэх мэт бүгдийг. Амралттай үед сонгож болно.
  • Ботыг чимээгүй болгох цаг — handoff гарсны дараа автомат хариултыг хичнээн цагт зогсоох (анхдагч 2).
  • Telegram chat ID-ууд — мэдэгдэл хүлээн авах chat ID-ууд (бүлэг чатын ID-г сөрөг тоо хэлбэрээр).
  • Туршиж үзэх товч — Telegram-ын холболтыг даруй шалгахад зориулсан.
  • Дуун дохио — админ хуудсан дээр шинэ handoff гарвал товч дуу гаргах.

12. Админ хэрэглэгчид (/admin/admins)

Хоёр түвшний эрх: admin (бүх админ үйлдэл) ба super_admin (нэмж: админ нэмэх / устгах / нууц үг шинэчлэх / эрх солих). Нууц үг хамгийн багадаа 12 тэмдэгт байх ёстой.

Нууц үгээ мартсан тохиолдолд Render-ийн RESET_ADMIN_USERNAME ба RESET_ADMIN_PASSWORD орчны хувьсагчид утга өгч, дахин deploy хийгээд, нэвтэрсний дараа эдгээр хувьсагчийг устгана.

13. Алдааны шийдэл

Бот хэрэглэгчид хариулахаа больсон

/admin/issues-н дээд хэсэгт байгаа "Бот чимээгүй байгаа хэрэглэгчид" картыг шалгана уу. Тухайн хэрэглэгчийн ботыг асаах боломжтой.

Шинэ handoff гарсан ч Telegram дээр мессеж ирэхгүй байна

Settings → "Туршиж үзэх" товчийг дарж шалгана уу. Алдаа гаргавал диалог нь шалтгааныг харуулна (token буруу, chat ID буруу, бот руу /start бичээгүй гэх мэт).

Нэр "Unknown" гэж харагдаж байна

Facebook апп Development mode-д байгаа бол ажилтан биш хэрэглэгчдийн нэр татагдахгүй. App Review хүлээгдэж байгаа эсэхээ шалгана уу. Бэлэн болсон дараа /admin/leads-н "Нэр шинэчлэх" товчоор бүгдийг нь шинэчлэх боломжтой.

Бот зөв хариулж чадахгүй болсон

"Алдаа гарсан асуулт" болгонд /admin/training-н "Нэмэлт тайлбарууд" хэсэгт нэг шинэ snippet нэмж бай. Энэ нь хамгийн үр дүнтэй сургалтын арга юм.

1. Overview

Magic Bot is a single-codebase, multi-tenant Flask app that connects a Facebook Page to OpenAI's Chat Completions API to auto-reply in Mongolian. One service instance backs one Facebook Page; multiple businesses are served by cloning the Render service and overriding a small set of branding-related environment variables.

3. Multi-tenancy

All branding/persona is environment-driven so the same code runs for any business: TRAINING_CONTENT, BOT_PERSONA, COMPANY_*, PRODUCT_NAME, SEED_DEFAULTS. To onboard a new bot: clone the Render service, point it at a new Facebook App + Page, override the env vars, set SEED_DEFAULTS=false so it doesn't inherit Magic's catalog.

5. Webhook lifecycle

POST /webhook handler steps:

  1. Verify X-Hub-Signature-256 against HMAC-SHA256(body, FACEBOOK_APP_SECRET). Skipped with warning if secret unset.
  2. Log delivery object + entries + sender IDs.
  3. Per-sender sliding-window rate limit (default 5 msg / 60s). Over-limit users get one polite throttle reply.
  4. Get-or-create FacebookUser by PSID. Lookup name via FB Graph; retry on subsequent messages if name still empty.
  5. Classify session state from prior message timestamp (new / active / gap / returning).
  6. Advance funnel stage (no regression).
  7. Persist inbound message.
  8. Mute check: if bot_muted_until > now, skip everything below. Auto-clear expired mutes.
  9. Handoff check: should_handoff() on the message. If positive: trigger handoff (send waiting reply, mute, create issue, Telegram notify) and stop.
  10. Build system prompt: persona + base training + active snippets (high priority first) + courses + FAQ + team + business lines + funnel/session rules.
  11. Call OpenAI with last 10 messages of conversation history.
  12. Persist outbound message, send via FB Send API.
  13. Phone regex on inbound message; if matched and not yet a lead, mark is_lead, save phone, send a "thank you for the number" reply.

6. Handoff logic

Three sensitivity tiers, controlled via handoff_sensitivity setting:

  • conservative (default) — explicit stem matches (ажилтан / оператор / менежер / хүнтэй / live agent / human / etc.) + business-line refer matches.
  • balanced — adds frustration phrases (болохгүй байна / ойлгомжгүй / гомдол / utgagүй / etc.).
  • aggressive — adds repeated-question detection (same message 3× in 1h).

Stems are deliberately short to defeat Mongolian agglutinative suffixes: 'ажилтан' catches ажилтантай / ажилтанд / ажилтны / ажилтнаас, etc. On match: trigger_handoff() sets bot_muted_until = now + mute_duration_hours, creates AdminIssue with issue_type='handoff', sends the user a polite waiting reply, fires Telegram notifications.

7. Funnel + session

Funnel: curious → exploring_courses → pricing → ready. Detection is keyword-based, never regresses. Stage drives a per-stage prompt section guiding the bot's tone (informational at curious, registration push at ready).

Session classified from time since last message: new / active (<2h) / gap (2-24h) / returning (24h+). Drives greeting behaviour (don't say "Сайн байна уу" mid-active conversation).

8. Notifications

Two channels, both optional:

  1. Telegram — send_telegram_notification(text) reads TELEGRAM_BOT_TOKEN from env, chat IDs from the telegram_chat_ids setting (comma-separated; group IDs are negative). Fires on every handoff. Silent no-op if the token env var or the chat IDs setting is empty — the handoff itself still completes, only the Telegram leg is skipped. Per-recipient errors are logged but never block the handoff.
  2. In-dashboard — every admin page polls /admin/api/handoff-poll every 15s; localStorage tracks the last-seen issue id. On new id, plays a beep via Web Audio API (oscillator → gain → destination, no asset file) and shows a red toast.

10. Deployment

  1. Create a Render web service from this repository. Procfile points gunicorn at app:app.
  2. Set the required env vars. SQLite without a persistent disk gets wiped on every redeploy — for production attach a Render persistent disk at /var/data and set SQLALCHEMY_DATABASE_URI=sqlite:////var/data/magic_bot.db.
  3. In the Facebook Developer Console: webhook URL = https://<render-url>/webhook, verify token = your VERIFY_TOKEN, subscribe the page to messages events.
  4. For Live mode: submit pages_messaging for Advanced Access via App Review. Without it, only people with app roles can chat with the bot and have their profiles resolved.
  5. Privacy policy URL = https://<render-url>/privacy.

11. Schema migration

init_db() runs on every boot (gunicorn worker import). It does db.create_all() for new tables and calls ensure_schema() which uses SQLite-style ALTER TABLE ADD COLUMN (also valid on Postgres) to add columns introduced after the first deploy — currently funnel_stage, last_nudge_at, bot_muted_until. Idempotent: skips additions that already exist.

12. Security

  • Webhook signature verification — HMAC-SHA256 against the raw body. Mandatory in Live mode.
  • Rate limiting — sliding window per sender (in-memory; for multi-worker swap to Redis).
  • Admin password policy — minimum 12 characters, hashed with Werkzeug's PBKDF2-SHA256.
  • Role tiers — destructive admin actions (create / delete / role change / password reset) require super_admin.
  • Last super_admin protection — can't delete or demote the last super_admin or the last admin.
  • Auto-self-heal — if a deployment has admins but none are super_admin, the oldest is promoted on boot.

13. Known limitations

  • SQLite + multi-worker gunicorn — fine for one or two workers under low load; under higher concurrency move to Postgres.
  • Rate-limit state is in-memory — each gunicorn worker has its own counter. Scale-out requires Redis.
  • OpenAI cost per inbound message — every non-handoff, non-muted message hits the API. Aggressive rate limits, business-line refer, and snippet quality are your levers.
  • Name lookup depends on FB permissions — Development mode + non-app-role users → name stays "Unknown" until pages_messaging gets Advanced Access.
  • Polling auto-commenting is off by default — turning it on with multiple gunicorn workers will produce duplicate comments. Run one worker if you enable it.
